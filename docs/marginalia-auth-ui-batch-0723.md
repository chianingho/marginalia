## 二、登入頁改版

**檔案**:`src/pages/Login.jsx` 及其對應樣式。

### 2-1 版面

由上而下垂直置中,單欄:

```
Marginalia          ← wordmark
閱讀筆記            ← 副標
(56px 間距)

(22px 間距)
──── 或 ────         ← 分隔線
```

### 2-2 Wordmark

- 字體:`var(--font-serif)`(**不得寫死 `'Fraunces'` 字串**)
- `font-variation-settings: 'opsz' 144`(光學尺寸軸,不設會失去粗細對比)
- `font-weight: 400`
- `font-size: 46px` 為起始值,**需對照書櫃橫幅的視覺重量微調**,以實機為準
- 顏色:品牌綠
- **不加螢光筆掃痕、不加任何裝飾元素**

### 2-3 副標「閱讀筆記」

- 字體:Noto Serif TC,15px,weight 400
- **必須明確設定 `letter-spacing: normal`**
  (現行版本繼承了 Latin 大寫的字距設定,中文被拉開,這是本次要修掉的主要問題之一)
- 顏色:品牌綠的淡化版本或既有次要文字 token

### 2-4 Google 登入按鈕

- **不得沿用 `.add-page-btn.btn-frosted`。**
  理由:frosted glass 需要背景有內容可模糊,登入頁是純色背景,`backdrop-filter` 無作用,
  只會留下半透明色 + 過重陰影。這是元件層級誤用,不是樣式微調問題。
- 改為:**實心品牌綠膠囊**,寬度 100%,高度 52px,`border-radius: 26px`,無邊框
- 陰影:無,或極輕(現行版本陰影過實,與整體柔和調性不符)
- **不得刪除或修改 `.btn-frosted` 這個 class 本身**,其他頁面仍在使用

### 2-5 Google G 圖標(合規要求)

使用者已提供官方資產 `google-color.svg`(四色版,`viewBox="0 0 24 24"`)。

- 放置於專案的靜態資產目錄,**內容不得修改**(不得改色、不得改比例、不得重繪)
- 呈現方式:白色圓形底 26px,內含 16px 的 G
- **白底是 Google 品牌規範的硬性要求**,四色 G 必須置於白色背景上
- 圖標左、文字右,間距 11px,整組水平置中
- 注意:該 SVG 路徑實際佔用約 1~23 單位,四邊各有 1 單位留白。
  用 flex 置中後**需以肉眼確認光學重心**,必要時微調

**已知不合規項目(刻意接受,不需處理)**:
按鈕文字使用 Noto Serif TC 而非 Google 規範的字體。
目前 OAuth 停留在 External + 測試使用者名單,不送驗證,故不影響。
若日後要送 app 驗證,此項需回頭處理。

## 三、訪客模式

### 3-1 核心要求:訪客是獨立的第三種模式

目前資料層有兩種狀態:有 session(走 Supabase)/ 無 env(走 localStorage)。
訪客是**第三種**:有 env、有能力連雲端,但使用者主動選擇不登入。

- **不得直接複用 `hasActiveSupabaseSession()` 回傳 false 的分支語意**來實作訪客
- 需要一個獨立且明確的訪客狀態旗標
- 資料層在判斷走雲端或本機時,必須能區分「未登入」與「訪客」

### 3-2 資料隔離(本項最重要)

訪客期間寫入的書與筆記,**絕對不可以被日後的一次性遷移函式掃到並上傳**。

- 訪客資料寫入**獨立的 localStorage / IndexedDB 命名空間**(與既有資料 key 不共用)
- 第 2 階段的遷移函式只讀取原有命名空間,不碰訪客命名空間
- `marginalia_migrated` flag 的判斷邏輯不受訪客模式影響

**風險說明**:若訪客資料與本機既有資料混在同一組 key,demo 訪客隨手新增的測試書
會在使用者本人下次登入時被遷移上雲,污染正式書櫃。此為不可逆的資料污染,務必隔離。

### 3-3 訪客中途登入

- 書櫃頁原本放頭像的位置,訪客模式下顯示 **`Sign in` 文字鈕**(英文,純文字階層)
- 點擊 → 走一般 Google OAuth 流程
- 登入成功後:畫面顯示**雲端資料**
- 訪客資料:**不上傳、不保留、也不主動清除**(留在獨立命名空間當作無害殘留)

### 3-4 不做的事

- **不在書櫃頁常駐任何訪客模式提示**(警語只在登入頁講一次)

### 3-5 驗收

- 以訪客進入 → 新增一本書 → 重新整理仍在
- 回 Supabase Table Editor 確認 **`books` 表沒有新增任何列**
- 訪客狀態下點 `Sign in` → 完成登入 → 書櫃顯示雲端資料,訪客那本書不在其中
- iPhone Safari 截圖

## 四、Splash 動畫接在登入之後,並兼作 session 判定遮罩

### 4-1 三條路徑

| 情境 | 流程 |
|---|---|
| 首次登入 / session 過期 | 登入頁 → OAuth → splash → 書櫃 |
| 已有 session | **splash(同時背景判定 session)** → 書櫃 |
| 訪客 | 登入頁 → 點 Continue as guest → splash → 書櫃 |

### 4-2 遮罩行為(本項的關鍵)

已有 session 時,進站**直接播 splash**,`getSession()` 在同一時間於背景進行。

- **不得先畫登入頁再跳走**,任何形式的閃爍都視為未通過
- 若 session 判定比動畫**快** → 等動畫播完再進書櫃
- 若 session 判定比動畫**慢** → 動畫播完後停在最後一格,直到判定完成
  (**不可退回登入頁再跳進書櫃**)
- 若判定結果為「無 session」→ 動畫結束後進登入頁

### 4-3 沿用既有原型

splash 已有可運作的 HTML 原型(純 CSS transition + 短 JS timeline),
含 `prefers-reduced-motion` 支援與點擊跳過。整合時保留這兩項行為。

`prefers-reduced-motion` 開啟時仍需正確完成 session 判定與導向,不可因跳過動畫而略過判定。

### 4-4 驗收

- 已登入狀態重新整理數次,錄影或連續截圖確認**全程無登入頁閃爍**
- 開啟系統的減少動態效果後重測一次
- iPhone Safari 實機

## 五、頭像與登出下拉

### 5-1 頭像

- 來源:`user.user_metadata.avatar_url`(Google 提供)
- **此為外部 URL,必須經 `isExternalUrl` 判斷直接跳過**,
  不得送進 `createSignedUrls`(與 Google Books 封面同一條路徑)
- 圓形,直徑與相鄰的 `.pill-btn` 一致(用變數或量測,不得寫死)
- **必須有 fallback**:圖片載入失敗時顯示 email 首字 + 品牌綠圓底
  (Google 頭像 URL 會有被擋或 429 的情況,無 fallback 會開天窗)

### 5-2 下拉內容

兩層,由上而下:

1. 目前登入的 email — 使用既有 `.meta-text`,不可點
2. 分隔線
3. 登出

- **不預留其他項目**
- **不得使用原生 `<select>`**(樣式無法控制)
- 需處理:點擊選單外部關閉、safe-area、下拉不被裁切
- **移除原本的 `confirm()` 二次確認**。資料已在雲端,登出不會遺失,兩段點擊已足夠

### 5-3 治理註記

前一批次遺留的爭議項(登出鈕 spec 寫 chevron tier、實作為 `.pill-btn` 圓形)
**因本次設計變更而失效,不再追認亦不退回**。
頭像屬身分識別元件,不納入導覽按鈕的 tier 系統。此裁示請記入 `ARCHITECTURE.md`。

### 5-4 驗收

- 頭像正常顯示
- **手動測 fallback**:暫時把 avatar_url 改成無效值,確認首字圓底出現
- 下拉開合正常,點外部可關
- 登出 → 回登入頁,書櫃不可見
- iPhone Safari 截圖
